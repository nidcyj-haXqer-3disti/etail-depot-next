# Experience implementation gap audit

Date: 2026-09-09. Baseline: `amex-public-v2`; target: 100% of the retained 90 public comparison tasks in every domain, plus all 20 mandatory gates. This audit does not change that inventory or its denominators.

This is an independent source assessment of the current local implementation, including the new access, session security, historical reports and private support modules. **Implemented** means the described local behavior exists in source; **partial** means a material part remains; **missing** means the required owning workflow does not exist. These labels are not verification points, a completion percentage, Amex visual similarity, or permission to release. Every task still needs its five canonical evidence dimensions. A generic support case is not an issuer dispute, a blocked draft is not an issuing decision, and a historical report is not an official financial statement.

Inspected sources: [account selection](../src/modules/accounts/service.ts), [policy](../src/modules/policy/evaluate.ts), [access commands](../src/modules/access/service.ts), [workspace commands/projections](../src/modules/workspace/service.ts), [cards](../src/ui/workspace/cards.tsx), [activity](../src/ui/workspace/activity.tsx), [merchant](../src/ui/workspace/merchant.tsx), [reports](../src/modules/reports/service.ts), [report derivation/CSV](../src/modules/reports/derive.ts), [session security](../src/modules/identity/security.ts), [security UI](../src/ui/workspace/security.tsx), [membership estimate](../src/modules/membership/estimate.ts), [support](../src/modules/cases/service.ts), and [support UI](../src/ui/workspace/cases.tsx). Existing and newly written unit/integration/API/browser tests were inspected. Focused support checks (4 unit and 8 PostgreSQL integration) and access checks (7 unit, 10 PostgreSQL integration and 4 PostgreSQL concurrency) passed in their module runs. The later card URL/navigation changes were inspected in source and in written regression tests; this audit does not claim their final combined browser verification. Final browser/release checks remain separately coordinated.

The connected Seller slice adds [named entry/setup and private request drafts](../docs/SELLER_ENTRY_EXPERIENCE.md). Merchant rows 01 and 04 now have partial local implementations; publication, actual approval and the financial lifecycle remain missing. Every canonical comparison assessment remains unassessed.

## Dependency order for further completion

The highest-value remaining end-user work is:

1. **Keep activity and exports in the same context** (AX-CONSUMER-03/04). Preserve search, dates, status, card and selected transaction through navigation/reload; carry the chosen filters into the server-authorized export; distinguish restricted/unavailable data from a true empty result. This can be completed against the existing historical records and policy. It does not require hosted Identity, a live provider or a financial ledger. The corrected card-detail URL behavior is already present in source and should be verified, not rebuilt.
2. **Give saved applications a useful next step** (AX-ISSUING-04–09). Add applicant-owned information tasks, versioned consent/review and named guardian/company approval handoffs to the existing request owner. Nonfinancial local task/consent drafts can be developed now. Effective eligibility, approval and issuance cannot be inferred from those drafts: they need the defined responsible party, sponsorship/funding assignments and the EDN-009/010 prerequisites. Unknown product or consent requirements must remain explicit instead of being guessed.
3. **Complete one durable fictional purchase before adding money-action screens** (AG02/04/05/06/14; AX-CONSUMER-07–11 and the financial Merchant rows). The existing historical snapshots cannot support an effective limit change, repayment, refund or payout. The actual implementation dependency is the single exact ledger, atomic backing/funding rules and the same durable command/event path used by the mock adapter. Resolve [D14–D17](../docs/DECISIONS.md) for their affected writes: monetary rounding; membership-year/refund/proration boundaries; sponsoring-membership attribution; and Household facility/backed-allocation choices. These local financial simulations do not require live card/bank credentials. Real money remains disabled.
4. **Make documents, evidence and follow-up durable** (AX-CONSUMER-06, AX-MERCHANT-17, AX-MANAGEMENT-07/13/16/18). Private attachment ownership, file validation, immutable versions, job status, authorized downloads and notification events need implementation; creator-private text cases and synchronous CSV exports do not supply them. Local adapters and failure/retry tests can be built without external delivery. Actual email, hosted storage and provider evidence submission need their own configured adapters, authorization and acceptance. Issued financial statements and financial case outcomes additionally require the underlying reconciled records.
5. **Let a new person join without a fixture login** (AX-CONTROLS-02 and AX-CONSUMER-17). Hosted individual sign-in, confirmation, invitation recovery and password/MFA recovery require the new Identity lifecycle to be configured and accepted. Custom sender/domain changes retain [D19](../docs/DECISIONS.md)'s separate approval boundary where applicable. This is a genuine hosted-acceptance dependency, not a reason to stop independent local UI/domain work.

Follow each original EDN dependency in [the backlog](backlog.json) when declaring an issue or milestone complete. The proposed local slices above do not close a dependency-gated issue, waive hosted acceptance or redefine the 90 tasks. Live-release decisions in D18, hosted-resource acceptance and review/publication approvals remain distinct from permission to implement and test the local sandbox. No requirement for a live provider should be invented for a mock-only workflow; no missing ledger, policy decision or approval should be concealed with a success screen.

No verified score is computed here. The baseline entries and mandatory gates retain their independent evidence/release requirements.
