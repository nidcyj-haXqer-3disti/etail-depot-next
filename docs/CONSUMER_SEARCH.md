# Consumer search and public release

Etail Depot now has four public information pages: `/`, `/card-services`, `/payment-services` and `/help`. Each uses the same reviewed metadata helper for a distinct title, description, canonical URL and social preview. Canonicals use only the recorded new-site origin, `https://etail-depot-next.netlify.app`; customer IDs, query parameters and request headers never choose that origin.

The application remains a local sandbox. **Google indexing is disabled, and this work does not publish the site or establish that Google has indexed it.** Root metadata is `noindex, nofollow`; private service, sign-in, security, checkout and operator pages inherit it. Their records never enter the sitemap. Authentication and server permissions protect private data; search directives do not provide access control.

`PUBLIC_INDEXING_APPROVAL` in `src/modules/public-site/metadata.ts` is deliberately `null`. No environment flag can approve indexing. After explicit public-release approval, a reviewed source change must record the exact site ID, canonical origin and approval reference. The guard also requires the matching production site, `APP_ENV`, deployment context and public origin. Local, test, branch and deploy-preview contexts stay non-indexable. Sitemap generation remains empty until that entire boundary is satisfied, then contains only the four public URLs. No automatic timestamp or guessed update frequency is advertised.

The Next root metadata supplies the private default. Only public pages call `publicPageMetadata()` to override it, and only those pages render `PublicPageStructuredData`. Structured data identifies the known brand, website and informational page; it makes no claims about banking status, licensing, rates, ratings or live products. `/opengraph-image` renders a generic 1200×630 branded image without fetching assets or reading customer data. Its response remains `noindex` while release approval is absent.

`robots.txt` permits HTML crawling so a crawler can observe the page's `noindex` directive, while excluding API crawling. It advertises a sitemap only after approval. Google explicitly distinguishes crawling from indexing: disallowing a page can prevent Google from seeing its robots metadata. [Google robots directives](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)

The sitemap and canonical links consistently use the same absolute URLs. A sitemap is a discovery hint, not a guarantee of crawling, indexing or ranking. After an approved release, inspect the actual production HTML, headers, sitemap and social image; verify the new property in Search Console and submit the sitemap through its authorized owner. Search Console verification, submission and indexing have not been performed here. [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [Google canonical URLs](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

Implementation follows Next's metadata and file conventions, including the root default and per-page overrides. Parent metadata fields are inherited unless overridden; public canonical links therefore live on the public pages, not the global layout. [Next metadata API](https://nextjs.org/docs/app/api-reference/functions/generate-metadata), [robots route](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/robots), [sitemap route](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap), [social image convention](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/opengraph-image). Primary documentation was checked on 2026-09-10.

Regression checks cover the closed approval gate, mismatched environment/site/origin, exact public inventory, private-path rejection, safe structured data and inherited private defaults. Run `pnpm exec vitest run tests/unit/public-seo.test.ts`. The final production build and browser checks remain separate evidence. Netlify's publication hold is unchanged; a GitHub push does not authorize removing it.
