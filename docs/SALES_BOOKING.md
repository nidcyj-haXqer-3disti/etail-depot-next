# Contact sales booking

## Prepared integration

Contact sales in the shared header opens the booking panel directly on the current page. Pricing, merchant and software partnership sales actions use the same panel. Their existing contact anchors remain the inactive-configuration fallback; there is no global link interception. The native link points to the approved public booking page, so it still works without JavaScript or when opened in another tab.

The general footer Contact link still opens `/company/contact`. Its sales section shows **Book a call** when booking is active. The email address stays in account and integration support. While the booking URL is `null`, sales retains an email link as a temporary fallback.

Existing account and store-integration support has its own section at `#account-support`, with `#integration` retained there. Setup guides and missing-payout links reach support rather than the sales booking panel. Card inquiries, privacy requests and the fixed application entrance remain separate. All contact emails work without JavaScript.

The public booking destination is `salesBookingUrl` in `src/shared/site/hosted-services.ts`. After account setup, set it to the operator-confirmed public team-page URL in the form `https://calendly.com/team-name`, or a public event URL in the form `https://calendly.com/account/event`. Do not add credentials, query parameters, email prefill or fragments. Invalid configuration fails the page build. A `null` value disables booking again.

The current website opens the approved single-host event directly, following the operator’s request to remove the intermediate team/event list. Keep the verified duration and host beside the URL in `hostedServices.sales`; update them whenever the provider event changes. The compact panel uses the existing Etail wordmark, a white surface and dark green controls. Its visible header shows the configured host and duration, with “Book a call” as its accessible dialog name. The provider’s repeated event introduction is hidden, while essential appointment details remain visible before submission. The desktop panel is 600 pixels wide and becomes full screen on narrow phones. Short, wide screens use a compact header row so the calendar has more room while Close and the fallback remain visible. Avoid adding another introduction or selection step above the calendar.

The shared `src/shared/ui/sales-booking/` components use Calendly's supported iframe option, created only when the visitor selects a sales link. The dialog is rendered under the document body so page styles and the mobile menu do not interfere. Opening it closes the mobile menu. Closing it restores focus to the visible sales link or the mobile Menu button. It uses no provider script, API token, database or server endpoint. The native link works without JavaScript. The panel keeps Close and the native fallback outside its one scrolling calendar area, with a fixed viewport layout on phones. It has an always-visible Close button, Escape dismissal from its own controls, restored focus and an Open booking in a new tab fallback link. A cross-origin provider frame can consume Escape when focus is inside it; keep Close accessible and do not attempt to bypass the browser boundary. Closing it removes the frame. Existing email contact remains available. The iframe adds Calendly’s documented `embed_type=Inline`, `embed_domain` containing only the current website host, `hide_event_type_details=1` and fixed Etail color parameters. These remove standalone framing and the repeated event introduction. Cookie controls remain visible. No SDK or postMessage listener is loaded. The configured public URL remains query-free. No visitor query, prefill or referrer is forwarded. Calendly handles the scheduling form and its cookie controls.

## Branding

Use the approved Etail logo and turn off Use Calendly branding in the organization owner's Branding settings, applying both choices across the organization. Team/shared events inherit the owner's promotional-branding setting. Use neutral customer labels in the website panel, including its fallback link, loading message and iframe title. Keep provider names in technical records and factual privacy disclosures.

Promotional branding removal is not full white labeling. Calendly controls its booking form, Terms and Privacy wording, notification senders and cancellation/rescheduling destinations. Do not obscure that text, hide cookie controls or claim there is no provider exposure. Check the actual configured team event before activation, including eligible-plan color support and the customer emails.

## Staff booking arrangement

The operator initially chose visitor-selected staff booking, then requested direct access to the calendar while only one host is available. The account owner is an administrator, not a meeting host. Start with the one staff member identified by the operator; keep names, invitation status and account-specific records in the private workspace until public booking details are approved.

The existing company Team Page can hold a host-specific event for each participating staff member. Calendly documents creating a Collective event with only that one host selected, and including the host’s name in the event title. The website currently links directly to its single approved event. If additional hosts are introduced, explicitly review the host-choice experience and website destination rather than silently switching users back to the team list. Do not put the administrator into the host list by default.

Calendly requires at least two active organization users to create a Team Page. The administrator can remain outside the host list. The invited staff member must accept the invitation, connect their own calendar and confirm working hours, time zone and meeting location. Do not use the administrator’s browser time zone as the staff schedule. Verify the real Team Page and appointment flow before website activation. If the operator explicitly skips a test appointment, record that decision and identify the unverified email, calendar-entry and cancellation behavior rather than claiming a complete appointment test. See the current work context for provider setup status. A team page without configured hosts and events is not ready for website activation.

Official instructions: [Set up a Team Page](https://calendly.com/help/how-to-set-up-a-team-page) and [let invitees choose their host](https://community.calendly.com/featured-tips-tricks-32/how-to-let-invitees-choose-their-host-using-a-team-page-4066).

## Activate staff booking

Provider requirements were rechecked on 11 November 2026. The [official signup page](https://calendly.com/signup) offers email, Google and Microsoft signup without a credit card. The basic iframe integration works with all Calendly plans. Removing promotional branding and customizing embed colors require an eligible paid plan. Account creation, calendar access and event configuration still require the operator.

1. Sign in to the company-owned Calendly account. Confirm that the invited booking account has accepted and has a working calendar. A shared email alias is not necessarily a calendar account. Keep invitation and calendar details in the private workspace.
2. Each participating staff member connects their calendar and selects the calendars that should block unavailable times. Confirm that invitations use the intended staff email. The account owner does not need a connected calendar when acting only as administrator.
3. Create a staff-specific sales-call event on the Team Page, with only that staff member assigned as host. Set duration, working hours, time zone, notice, buffers, meeting location and cancellation/rescheduling rules. Google Meet is optional. When the operator chooses manual meeting details, use a custom location visible before booking and clearly state that the team will email the details. The team must send them before each appointment; Calendly will not generate a video link for that custom text.
4. Keep the booking questions short: name, work email, company website and topic. Configure reminders and sender settings in Calendly. Do not assume all Calendly emails come from the connected company address.
5. Copy the approved public event link for direct calendar access and confirm its host, duration and location. Use a Team Page only when a host-choice step is intentionally requested. Review the Website Privacy Policy against the configured scheduling and cookie behavior, and update its factual disclosures before activation. Set the one source value above. Account credentials stay out of source and chat.
6. Rebuild and run the contact booking, commercial-page, page-paint and accessibility checks. Review the real event on desktop and mobile, including its cookie controls and visible branding. The website styles the panel; Calendly controls the form. Do not change the operator’s subscription or add seats as part of website activation.
7. With the operator, make a test appointment and verify availability conflicts, time-zone handling, the calendar entry, intended email sender, confirmations, reminders and cancellation. Local fixture tests do not verify these provider settings.
8. Use the normal authorized PR and manual Netlify release process. After publication, check direct sales booking and the separate support email on the live site.
