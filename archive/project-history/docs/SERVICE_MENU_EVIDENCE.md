# D77 verification — service menu hierarchy

13 September 2026. Scope and reference interpretation are in [the menu contract](SERVICE_MENU_HIERARCHY.md). This record distinguishes application checks, visual review and publication. No database migration, reset, financial-policy change, external provider connection or real-money action belongs to this slice.

## Implementation

Card navigation separates Account home, Cards, Activity, Account balance and Account settings. Cards contains All cards, Cardholders and Card history. Its single Add card action invokes the existing issuance flow; assignment remains attached to the created card. Holder menus omit owner money controls. Account balance uses the existing canonical funding/withdrawal workspace; the former card funding form no longer starts new requests, while saved reviews and receipts remain recoverable.

Merchant navigation remains visible inside a terminal and balance task. Account home is a compact overview; Payments retains the saved investigation. Terminal channels, payments, team access, disputes and settings stay below the selected terminal. Business details and money tasks retain validated terminal/date/search context. The contextual View all payments action starts a fresh payments list within the selected terminals.

Review identified and corrected navigation-specific defects: denied merchant money access needed a deliberate exit despite the pending-request navigation guard; submitted business details must use owner authority for menu visibility rather than form-edit eligibility; View all payments must not reopen a previously filtered refunds list. Tests retain exact-resource access, original command identity and single posted financial effect checks. Historical receipts now retain the account menu; recipients with several cards in one invited account can open Activity by that account context, while recipients of unrelated accounts still choose a scope.
