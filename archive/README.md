# Historical project records

These files are preserved public repository history. They are excluded from the website and deployment package. This directory is not private storage and does not make any file confidential.

| Folder | What it preserves |
| --- | --- |
| [bootstrap](bootstrap/) | Initial starting prompts, handoff validation and the original package manifest |
| [project-history](project-history/) | Prior website plans, research, decisions, evidence and full status/instruction snapshots |
| [retired-platform](retired-platform/) | Old account-platform contracts, prompts, supplied requirements, sample templates and duplicate original brand material |
| [database](database/README.md) | Existing immutable migration/schema history; no customer database or active runtime |

The old `contracts/` records are retired application/API specifications. Current customer-facing merchant legal provisions live under `src/features/company/legal/`; they were not moved here.

Archived files retain their original bytes, dated wording, relative links and source paths. A historical “current,” “required” or “approved” statement belongs to that file's original context. The initial package manifest is an original handoff inventory, not a checksum of today's repository. Do not execute archived setup commands, CI templates, provisioning prompts or migrations. Do not repair archived database imports.

Use [the current instructions](../docs/REPOSITORY_GUIDE.md) and [current status](../docs/CURRENT_WORK_CONTEXT.md) for new work. The [Stage 4 receipt](../docs/plans/repository-stage4.json) maps original paths to their new locations and records byte-preservation checks. Git history retains the original contexts when an old relative link no longer resolves after relocation.
